## I. The Common Misunderstanding

TRIZ says: pursue the ideal. The ideal is the function without the mechanism.

Many interpret this as: move the mechanism outside. Externalize it. Hide it. Make it invisible.

This is a mistake.

Externalization is not the ideal. Externalization is just moving the accident elsewhere. The machinery is still there. The complexity is still there. It is just hidden, buried, or outsourced.

The user does not see it. But it is still there. It still pollutes. It still adds complexity. It still burdens the system.

---

## II. The Self-Cleaning Surface Example

TRIZ often uses the self-cleaning surface as an example of the ideal.

The function: clean surface.
The mechanism: a wiper, a spray, a person wiping.
The ideal: the surface cleans itself.

But what is actually happening? The mechanism is not eliminated. It is moved. It is embedded in the material, in the chemistry, in the environment. The cleaning function is performed by rain, by light, by the coating.

The machinery is still there. It is just externalized.

This is not the ideal. This is the illusion of the ideal. The machinery is hidden, but it is not gone. The complexity is moved, but it is not reduced.

---

## III. The Brick Example

TRIZ also offers the "fantastic brick."

A brick that does everything. It insulates. It conducts heat. It absorbs sound. It supports weight. It is cheap. It is strong. It is lightweight. It solves every problem.

This is the ideal in TRIZ's imagination.

But in reality, the brick is just a piece of machinery. It has properties. It has structure. It has complexity. The more functions it performs, the more complex it is. The more it does, the more machinery it contains.

The ideal is not a brick that does everything. The ideal is a solution that needs no brick at all.

---

## IV. The Real Ideal

The real ideal is not externalization. The real ideal is **minimization**.

The ideal is the accident that is **necessary and sufficient**. No more. No less.

- Not a brick that does everything.
- Not a surface that cleans itself.
- Not a payment app with screens, databases, and deployment.

The ideal is the solution that does exactly what is needed and nothing else.

- The solution that is exactly as large as the problem requires.
- The solution that uses the least possible machinery.
- The solution that preserves the substance without burdening it with accidents.

---

## V. The Substance-Accident Distinction

The substance is the problem and its resolution. The hunger. The pain. The need. The outcome.

The accidents are the implementations. The cash. The app. The bureaucracy. The machinery.

The ideal is the accident that is **minimal**—the smallest possible machinery that delivers the substance.

- If cash solves the problem, use cash.
- If a simple form solves the problem, use a simple form.
- If software solves the problem, use the smallest possible software.

The ideal is not "software that hides the machinery." The ideal is "software that uses the least possible machinery."

---

## VI. Why Externalization Is a Mistake

Externalization is a mistake because:

1. **It does not eliminate complexity.** It moves it. The complexity is still there, just hidden.

2. **It creates dependencies.** The externalized machinery becomes a dependency. The system relies on it. It cannot be changed without consequences.

3. **It is an illusion of simplicity.** The user does not see the complexity, but the complexity is still there. It still costs. It still breaks. It still needs maintenance.

4. **It avoids the real problem.** The real problem is not "how do we hide the machinery?" The real problem is "how do we minimize the machinery?"

The ideal is not externalization. The ideal is minimization.

---

## VII. The Connection to Empirical Software

Empirical Software is the application of this principle.

- The substance is the user's experience. What appears on the screen. What the user perceives.
- The accidents are the code, the framework, the database, the deployment.

The ideal is the accident that is **necessary and sufficient**—the smallest possible code, the simplest possible framework, the most minimal database.

Not "software that hides the machinery." Not "software that externalizes the complexity." Not "software that moves the machinery outside."

The ideal is "software that minimizes the machinery."

---

## VIII. The Correction

The correction is clear:

- Do not externalize. Minimize.
- Do not hide the machinery. Reduce it.
- Do not move the complexity. Eliminate it.
- Do not add more layers. Remove them.
- Do not build more abstraction. Build less.

The ideal is the accident that is **necessary and sufficient**. No more. No less.

---

## IX. The Test

Ask this question of any solution:

> **"Is this necessary? Is this sufficient?"**

If it is not necessary, remove it.
If it is not sufficient, add only what is needed.

The ideal is the solution that passes this test. The ideal is the accident that is exactly enough.
